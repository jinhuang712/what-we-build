# PHILOSOPHY.md

The philosophy is where the project thinks. It goes under the decisions to the beliefs they come from: what the problem is, why it is hard, and what the project holds to be true about it. It is a set of questions about the world the project works in. Each has a stance in one line that people quote, and an argument under it.

It comes second, after the proposal. DESIGNS builds on its stances.

**Owns:** the belief the project starts from, the questions it takes a stance on with their arguments, quotes from sources that shaped or tested them, *Reflections*, and the sources.

**Leaves out:** any feature, setting or screen (FEATURES), and how the project is built (DESIGNS).

**Push back on:** a stance with no argument, one no team would answer differently ("quality matters"), a quote that decorates and does not test, and a quote nobody checked.

## Guidelines

- **State each stance as one quotable line,** then argue it.
- **Test a stance against sources,** and list every quote in *Sources*.
- **Use the user's questions and the user's words.**

## Skeleton

```markdown
# Philosophy

<the belief the project starts from>

## <a question the project takes a stance on>

**<the stance, one quotable line>.**

<the argument>

## Reflections

<the thinking still in motion>

## Sources

- <author>. *<title>*. <year>.
```
