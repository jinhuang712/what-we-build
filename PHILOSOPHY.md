# Philosophy

A project begins as a feeling that something should exist. Before code, that feeling must become decisions: what hurts, what we want, what we refuse, how we will know. Documents are where those decisions live.

But a document cannot make a decision. It can only record one. Text written before the thinking is done looks finished and is not. It is confident about things nobody chose.

what-we-build exists so that the thinking happens first, together, and the writing follows. Every change to the skill is checked against this page.

## What clarity means

Clarity is not the absence of detail. It is knowing where each thing lives, and trusting that it is true.

A reader who must open five documents to find one fact does not have clarity. Neither does a reader who finds the same fact written three ways. Clarity is one question per document, and one answer per question.

## Principles

### 1. Talk before you write

A conversation can change its mind cheaply. A document resists change, because it already looks finished. So the decisions come first, one at a time, out loud. The document comes after, and it only records what was agreed.

### 2. One question, one home

When a fact has two homes, one of them will go stale, and the reader cannot tell which one. Give every document one question to answer, and every fact a single address. The other documents point to it.

### 3. The user decides

An agent can ask, compare and recommend faster than any person. It cannot know what the user wants until the user says so. A quick agreement is not help. The agent's job is to ask the question the user has not asked yet, recommend an answer with a reason, and then follow the user's call.

### 4. A number, or an open question

A vague goal feels safe because it can never fail. That is also why it is useless. When a goal has no number yet, say so and leave it open. An honest open question is worth more than a confident wish.

## Design guidelines

| Word | Means |
|---|---|
| **Plain** | Short words, short sentences, one point at a time. |
| **Honest** | Nothing claimed without evidence. Unknowns stay visible. |
| **Brief** | Say it once, in the right place. |
| **Patient** | One decision at a time. No doc before its time. |

## The test for every change

Before any change to the skill, ask:

1. Does it help the user decide, instead of deciding for them?
2. Does it keep one home for each fact?
3. Does it make the docs easier to read, not only shorter?
4. Would the user miss it if it were gone?

When the answer to 1 or 2 is no, the change does not belong in what-we-build.
